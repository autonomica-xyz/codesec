# Corrected benchmark results — 2026-07-24

## Outcome

The old ranking in `REPORT.md` is invalid and remains archived only for
provenance. A current-generation/security sweep changes the point-estimate
leader: Titus-Cybersecurity-35B reaches MCC 0.752, followed by OpenMythos-27B
at 0.709, base Qwen3.6-27B at 0.687, and Gemma-4-12B at 0.673. The top four
remain statistically indistinguishable on this small development set.

Titus is the recall-first model: it catches 97.5% of vulnerable instances but
accepts 71.7% of safe decoys. OpenMythos is better balanced, with 90.6% recall,
92.9% precision, 81.7% specificity, and the best CWE exactness at 82.8%.
An exploratory Titus-and-OpenMythos consensus reaches MCC 0.787, 90.6% recall,
96.7% precision, and 91.7% specificity. That ensemble result was discovered on
this development set and needs confirmation on a frozen holdout.

This is a 44-case development set, not an external holdout. The result supports
engineering decisions and regression detection; it does not establish a
general model leaderboard.

## Operational diagnostics

Gemma produced exact bare JSON for 75/220 requests (34.1%), although 219 had
an unambiguous parseable verdict. Its unresolved SSRF-allowlist decoy produced
multiple JSON objects, contradictory prose, and a truncated final object after
both attempts.

Qwen3.6-27B produced 218/220 exact and decidable responses (99.1%). One
redirect-allowlist answer hit the token cap with an unterminated string; the
tar argument-injection answer was unterminated twice.

These undecidable rows are not guessed, coerced to safe, or charged as
classification errors. They affect semantic coverage only. Raw attempts are
preserved under `bench/probe/results-v2/invalid/`. Full-coverage sensitivity
over every possible missing binary verdict is MCC 0.664–0.677 for Gemma and
0.669–0.691 for Qwen3.6-27B.

Qwopus and OpenMythos produced 220/220 exact JSON verdicts. Titus produced
220/220 semantically decidable, schema-valid verdicts, but its chat template
prepended an empty `<think></think>` block to every JSON answer. The parser
treats that single, structurally bounded reasoning envelope as transparent
while recording 0% exact formatting. The initial Titus artifact was rejected
at 0/220 coverage under the older parser and was rerun from scratch; it is not
used in the ranking.

CyberPal produced 217/220 decidable verdicts. Two responses had a dangling
closing Markdown fence and one contained unescaped quotes inside its JSON
reason. Those rows remain undecidable; assigning every possible binary value
to them bounds full-coverage MCC at 0.362–0.395.

Unsloth's proxy was not used for evaluation requests. A controlled live check
showed that it dropped per-request `chat_template_kwargs`, leaving Gemma and
Qwen3.6 templates in thinking-on mode. The finalized trials use Unsloth for
model selection/startup and send requests directly to the localhost
llama.cpp port, where `enable_thinking=false` was verified to change
reasoning output into normal content.

The community GGUF sweep used direct llama.cpp instead of Unsloth model
selection. Every repository revision was pinned in runtime metadata, one model
at a time was staged in `/dev/shm`, and `-ngl 999` requested full offload. A
launcher defect initially loaded Qwopus on CPU because the dynamic CUDA backend
and CUDA runtime paths were not exported. That attempt was stopped and
discarded. Final runs set both paths and fail unless process VRAM is at least
70% of GGUF size; Qwopus passed at 30,961 MiB process VRAM.

## Methodology fixes

The corrected harness:

1. keeps answer keys outside scan roots;
2. scans fresh root-owned, recursively read-only corpus copies and verifies
   before/after content hashes;
3. scores only final reachable/deduplicated repository reports;
4. requires exact basename plus source-line overlap and one-to-one truth
   matching;
5. corrects version-dependent and non-exploitable labels;
6. scores semantic verdicts as the north star while reporting unresolved
   parse/request failures separately as coverage;
7. validates embedded truth, complete `(case, repeat)` coverage, and dataset
   hashes;
8. uses MCC/balanced accuracy, clustered uncertainty, paired comparisons, and
   an explicit trivial baseline;
9. records exact quantization, runtime builds, GPU/VRAM, endpoint, prompt
   settings, raw responses, retries, and exact-format compliance;
10. documents the custom snippets as a development set and corrects the false
    claim that CyberSecEval was unavailable (the sparse-checkout path was
    misspelled);
11. pins community-model revisions, stages them in tmpfs, and gates direct
    llama.cpp runs on measured process VRAM so CPU fallback cannot pass;
12. reparses older raw artifacts only into non-overwriting, source-hashed
    derived files before cross-schema comparison.

See `METHODOLOGY.md` for the executable contract.

## Recommendation

For this A6000 host, advance Titus and OpenMythos to the end-to-end repository
trial, with Gemma-4-12B retained as the efficiency control. Use Titus as the
recall-first discovery model and OpenMythos as an independent validator:
intersection findings are high confidence, while Titus-only findings should
remain visible at lower priority. Do not threshold Titus's self-reported
confidence; on this set, raising the threshold reduced MCC from 0.752 to
0.656 or worse.

Qwopus does not improve overall detection balance over its base Qwen3.6-27B
control despite using Q8 here, and CyberPal's 41.7% specificity is too noisy
for primary code review. Neither should advance ahead of Titus, OpenMythos,
Gemma, or Qwen3.6-27B.

Do not compare these corrected local runs to the invalid old GLM run, and do
not make a final product choice without a frozen external
positive-and-negative holdout plus the read-only repository evaluation.
